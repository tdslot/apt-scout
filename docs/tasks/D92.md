# D92

State: READY; coverage, not a defect. The ledger holds the same state; this file holds the brief.

`TEST-9` says every call site that rewrites a control character is pinned by a test. Six are escaped and none is
pinned, and the counting test in `src/main.rs` cannot see them: it notices a removed call, not a call whose escape has
been undone. Each of the six was mutated to a no-op by the review of PR #123 and the suite stayed green except for the
count.

The sites: `plan_changes` prints the new file's bytes and both of its URI lines; `run` prints the Team Cymru lookup
failure, the reference-read warning's error text, and the `nothing to change` line with the best URL. Every one carries
text the run did not author — a mirror URI from the network, a DNS error, a URI read from the user's apt file.

Acceptance:
- the first three reach a test through a builder, the way `geolocation_note`, `fallback_warning` and `error_line` did in
  D91: `plan_changes` prints its file bytes and URI lines through functions a test can call;
- one test per site, with a control character fed in, and the mutation named in the PR for each;
- `TEST-9`'s `SPEC.md` row moves from `partial: six call sites are escaped and unpinned; D92` to implemented.

Not claimed: that a count test can replace these. It cannot, and this task exists because of that.
