No separate PR: docs/spec/testing.md now states the rule — an assertion compares a value with an expectation that does not derive from the same expression as the value — and every task that writes or changes a test applies it, which is what makes it a gate rather than a resolution. The rule earns its place from how the three were found, so each is recorded with the finding and the fix: (1) **an ownership assertion in the restore round trip** asserted the owner of a file it had just restored, and a non-root test's files are its own uid, so an `fchown` to that uid is a no-op that succeeds whichever way the writer treats ownership — found by reading the assertion against the environment it runs in while the restore engine was reviewed (PR #59/#60), and the owner comparison is now the container case W27, which runs as root and compares uid/gid against the pre-write state; (2) **an assertion on the baseline a restore hands the writer** was true of the outcome either way, because `check_freshness` returns early for a restore plan and accepts either value, so the assertion asserted nothing — found the same way, and closed by observing the argument through the `run_as` seam with a sentinel planted on the wrong side (`let mut handed = Some(0i64);`), so a `Some(..)` fails with `left: Some(...), right: None` (`restore::tests::run_restores_the_backup_and_a_second_run_is_refused`); (3) **a version assertion whose two sides came from one expression** compared the printed line with `env!("CARGO_PKG_VERSION")`, the same string `VERSION_LINE` interpolates, so it matched itself — found by the review of PR #63 and closed by recomposing the expectation from Cargo's split parts (`MAJOR`, `MINOR`, `PATCH`, `PRE`), so a hardcoded constant or a changed prefix fails instead of matching itself (`tests::version_is_two_spellings_and_the_line_is_the_crate_version`). Acceptance, and it is a review gate rather than a note: a task that writes or changes a test states in its PR the mutation the test survives — the code it covers is broken by hand, the test watched failing, the code restored — or says why no such mutation exists; a reviewer who cannot name that mutation does not pass the test; and `rg -n 'An assertion compares a value' SPEC.md` prints the rule.
