# D90

State: READY; the seam D89's container case needs. The ledger holds the same state; this file holds the brief.

Give a test a way to choose the mirror list the run reads, so a container case can feed a mirror URL that carries a
control character and grep the run's output for the raw byte. Today the binary fetches Launchpad and
`mirrors.ubuntu.com` and nothing else, and the injected `Fetch` exists only in unit tests, which is why D89's
end-to-end half did not land.

Decide first, in `docs/spec/` before any code:
- a `#[cfg(apt_scout_write_harness)]` subcommand beside the write harness, which ships in no release build, or
- a test-only environment read, which would be the fourth read the tool makes and would contradict the inventory in
  the record.

Acceptance:
- the seam exists only in a build that no release produces, and a release binary given the same input ignores it;
- one container case builds a rejected entry from a URL carrying `ESC` and asserts the raw byte is absent from stdout
  and stderr;
- D89's row moves from PARTIAL to DONE, with the container case named as its evidence;
- the `docs/spec/` chapter states which of the two forms was ruled and why, and the record's environment inventory is
  correct or the ruling says why it is unchanged.

Not claimed: that the seam is a product feature. It exists to make one assertion end to end.
